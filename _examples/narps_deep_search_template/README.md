# Design example: adaptive NARPS smoothing-mechanism search

## Status

This is an **unnumbered reference template** prepared on 2026-09-19. It is not
an episode and has no run, reward, approval, result, or scientific status. It
reserves no campaign identity.

Historical examples that motivated the template:

```yaml
counts_as_portfolio_episode: false
derived_from_historical_examples:
  - ../historical_prior_records/episode01_narps_analysis
  - ../historical_prior_records/episode02_narps_analysis
```

The two physical directories are immutable historical records. This template
does not rewrite either one. It treats their results as exposed development
lineage:

- Episode 01 established that smoothing dominated its frozen three-factor
  map-variance attribution in `ds001734`.
- Episode 02 ran two bounded mechanism tests and left important kernel,
  scaling, edge, uncertainty, and transport questions unresolved.

The template changes the unit of work from a one-batch preregistered test to a
budgeted search program followed by one external transport audit. It may inform
a future explicitly selected episode, but this directory does not create,
reserve, or propose one.

## Requirements before reuse

1. The generic Goal V3 path is not sufficient: it freezes at most two selected
   tests before target outcomes and has no multi-round incumbent/challenger
   controller. An instantiated episode must freeze `SEARCH_POLICY.md` and bind
   it to the run before candidate scoring.
2. The external `ds000005` audit must be made technically unavailable to the
   discovery process until configuration lock. A prose instruction or visible
   filesystem path is not an adequate audit firewall.
3. Development and audit inventories, source pins, contrast semantics, common
   spaces, and executable environments must be hash-bound before any run.
4. The audit thresholds in `GOAL.md` require outcome-blind synthetic
   calibration and scientist approval before any `ds000005` neural array is
   opened.
